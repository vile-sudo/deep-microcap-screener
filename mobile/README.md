# Deep Sweep -- mobile app shell

A thin native wrapper (Capacitor) around the live dashboard at
[deepsweep.pkresearch.in](https://deepsweep.pkresearch.in), for the Play
Store and App Store. It has no web assets of its own -- `capacitor.config.json`'s
`server.url` points the native WebView straight at production, so:

- An ordinary content/feature change (anything in `../backend` or
  `../frontend`) ships the normal way -- `git push`, GitHub Actions, AWS --
  and every install of this app picks it up immediately, with **no new app
  release**.
- A new store release is only needed for a change to *this* native shell
  itself: icons/splash (`resources/`), push notification wiring, native
  permissions, or `capacitor.config.json`.

The one thing the plain website cannot do that this app adds: **push
notifications** (News Channel today; see `../backend/app/push.py`). Real
native capability like this is also why Apple's App Review is expected to
accept this as more than "just a website in a box" (guideline 4.2.3) --
see MOBILE_SETUP.md.

## Layout

```
mobile/
  capacitor.config.json   server.url, app id, plugin config
  resources/              source icon.png (1024x1024) + splash.png -- see below
  android/                generated native Android project (npx cap add android)
  ios/                    generated native Xcode project (npx cap add ios)
  ios/inject_firebase.rb  wires GoogleService-Info.plist + push entitlement into
                          the Xcode project at CI build time -- see its own comment
```

`android/` and `ios/` are committed (Capacitor's own recommended workflow),
not regenerated on every build -- Codemagic just builds what's here.

## One-time local setup (only needed if you ever want to build locally
instead of via Codemagic -- see ../MOBILE_SETUP.md for the no-Mac path)

```
cd mobile
npm install
npx cap sync
```

Android: open `android/` in Android Studio, or `npm run open:android`.
iOS (needs a Mac): `npm run open:ios`, needs `pod install` in `ios/App`
first (CocoaPods).

## Replacing the icon

`resources/icon.png` and `resources/splash.png` were generated by upscaling
the web app's existing 512x512 icon (`../frontend/static/icon-512.png`) --
functional, but soft at full size. Before a real store submission, replace
`resources/icon.png` with a crisp 1024x1024 source, then:

```
npx capacitor-assets generate
```

This regenerates every Android density and iOS size from that one file.

## Push notifications

Uses `@capacitor-firebase/messaging`, not the plain
`@capacitor/push-notifications` plugin -- it converts iOS's native APNs
token into a real Firebase Cloud Messaging token on-device, so
`../backend/app/push.py` can send one Firebase call that reaches Android
and iOS alike. Needs a Firebase project's `google-services.json`
(Android) and `GoogleService-Info.plist` (iOS) -- see MOBILE_SETUP.md for
where those come from; both are gitignored (`.gitignore` in this folder)
and injected at CI build time from Codemagic secrets instead.

Registration flow: `../frontend/static/app.js`'s `mobilePushRegister()`
runs once the user is logged in and only `window.Capacitor.isNativePlatform()`
is true (i.e. never in a plain browser), asks for notification permission,
and posts the token to `POST /api/push/register`
(`../backend/app/routers/push.py`).
